Block by Block — stock forecasting checkpoint audit¶

Question: Does the repository's Transformer predict next-observation Close better than repeating the most recently observed Close?

Project context: Block by Block is a team-built financial AI toolkit combining forecasting, trading experiments, and a web interface. The hackathon edition, placement, and individual contributions remain unconfirmed.

Run scope: evaluate the existing checkpoint on 37 real stock datasets; retain its original architecture and original scalers. This is a new checkpoint audit, not a claim that the model was retrained or that historical model selection was independent of the test data. Source artifacts are pinned by commit and checksum in run-assets/block-source-manifest.json.

Decision criterion: lower MAE than last-close persistence, measured per ticker; report RMSE and normalized errors too. Forecast errors alone do not demonstrate profitable trading.

Shared-model design and unseen-ticker goal¶

The original pipeline concatenates training sequences from 37 stocks into one shared Transformer. The project goal includes exploring transfer to tickers not seen during training. The completed audit below evaluates later dates of the 37 known stocks; it does not test unseen-ticker generalization.

The original notebook holds out time within each stock, and its prediction API requires that ticker's saved scaler. A true unseen-ticker study would need complete stock-level holdouts and a past-only normalization policy for the new stock. Neither successful transfer nor arbitrary-ticker API support is claimed here.

GPU execution backend¶

The repository model was implemented with TensorFlow/Keras. This run restores the same Keras layer architecture and weights using Keras 3 with its PyTorch CUDA backend. This backend change is recorded explicitly; this is a checkpoint evaluation, not an exact recreation of the historical software environment. Keras supports backend selection as documented in its setup guide.

Split at 2024-01-01, then compute the original trailing indicators separately in each period. This preserves checkpoint compatibility; it also discards the initial indicator warm-up and ten-window observations from the test period. A redesigned experiment could carry already observed training history into test inputs, but would be a separate comparison.

Restore original per-ticker MinMax scalers. Compare their scale and offset with a fresh fit to the available pre-2024 engineered training rows; never fit or update scalers on test rows. A match supports preprocessing consistency, but cannot prove the weights never encountered test data during development.

# Feature Engineering: Add technical indicators
def add_technical_features(df):
    """Add technical indicators to the dataframe"""
    df = df.copy()
    
    # 1. Returns (daily price change percentage)
    df['Returns'] = df['Close'].pct_change()
    
    # 2. Moving Averages
    df['MA_5'] = df['Close'].rolling(window=5).mean()
    df['MA_10'] = df['Close'].rolling(window=10).mean()
    df['MA_20'] = df['Close'].rolling(window=20).mean()
    
    # 3. Exponential Moving Average
    df['EMA_12'] = df['Close'].ewm(span=12, adjust=False).mean()
    
    # 4. Volatility (standard deviation of returns)
    df['Volatility'] = df['Returns'].rolling(window=10).std()
    
    # 5. Price momentum
    df['Momentum'] = df['Close'] - df['Close'].shift(5)
    
    # 6. Relative Strength Index (RSI)
    delta = df['Close'].diff()
    gain = (delta.where(delta > 0, 0)).rolling(window=14).mean()
    loss = (-delta.where(delta < 0, 0)).rolling(window=14).mean()
    rs = gain / loss
    df['RSI'] = 100 - (100 / (1 + rs))
    
    # 7. MACD (Moving Average Convergence Divergence)
    exp1 = df['Close'].ewm(span=12, adjust=False).mean()
    exp2 = df['Close'].ewm(span=26, adjust=False).mean()
    df['MACD'] = exp1 - exp2
    df['MACD_Signal'] = df['MACD'].ewm(span=9, adjust=False).mean()
    
    # 8. Bollinger Bands
    df['BB_Middle'] = df['Close'].rolling(window=20).mean()
    df['BB_Std'] = df['Close'].rolling(window=20).std()
    df['BB_Upper'] = df['BB_Middle'] + (df['BB_Std'] * 2)
    df['BB_Lower'] = df['BB_Middle'] - (df['BB_Std'] * 2)
    
    # 9. Volume indicators
    df['Volume_MA'] = df['Volume'].rolling(window=5).mean()
    df['Volume_Ratio'] = df['Volume'] / df['Volume_MA']
    
    # 10. Price range indicators
    df['High_Low_Diff'] = df['High'] - df['Low']
    df['High_Low_Pct'] = (df['High'] - df['Low']) / df['Low']
    
    # Drop NaN values created by rolling calculations
    df = df.dropna()
    
    return df

Restore the exact checkpoint architecture on the GPU¶

The original encoder has 60 attention heads and a double residual expression; its ff_dim argument is unused. Pooling uses the original channels_first setting. Those choices are preserved so the saved weights remain compatible; they should be reviewed in any new training experiment. This is not a claim that these settings are optimal.

Keras 3 restores the repository weights using its PyTorch CUDA backend. No fresh learning curve is shown because there is no verified original training-history artifact. The historical notebook's validation split used concatenated ticker arrays, which does not establish a temporal validation split for each ticker.

def transformer_encoder(inputs, head_size, num_heads, ff_dim, dropout=0):

    # Normalization and Attention
    # "EMBEDDING LAYER"
    x = layers.LayerNormalization(epsilon=1e-6)(inputs)

    # "ATTENTION LAYER"
    x = layers.MultiHeadAttention(
        key_dim=head_size, num_heads=num_heads, dropout=dropout
    )(x, x)
    x = layers.Dropout(dropout)(x)
    res = x + inputs

    # FEED FORWARD Part - you can stick anything here or just delete the whole section - it will still work.
    return x + res

def build_model(
    input_shape,
    head_size,
    num_heads,
    ff_dim,
    num_transformer_blocks,
    mlp_units,
    dropout=0,
    mlp_dropout=0,
):
    inputs = keras.Input(shape=input_shape)
    x = inputs

    for _ in range(num_transformer_blocks):  # This is what stacks our transformer blocks
        x = transformer_encoder(x, head_size, num_heads, ff_dim, dropout)

    x = layers.GlobalAveragePooling1D(data_format="channels_first")(x)
    for dim in mlp_units:
        x = layers.Dense(dim, activation="elu")(x)
        x = layers.Dropout(mlp_dropout)(x)
    outputs = layers.Dense(1, activation="linear")(x) #this is a pass-through
    return keras.Model(inputs, outputs)

Held-out evaluation: does the Transformer beat last-observed-close persistence?¶

Predict every ticker once. Compare MAE and RMSE with a baseline that uses only the final observed Close in each input window. Keep per-ticker errors in a table; do not average raw dollar errors across differently priced stocks. Normalized macro errors are descriptive and not trading returns.

Evaluate all configured tickers¶

Inverse-transform actual, predicted, and previous-close values with each training-fitted scaler. Use target dates corresponding exactly to the test windows. Keep all tickers in the error table and reject mismatched dates or target columns.

Interpretation of the completed checkpoint audit (2026-10-06)¶

Decision: keep last-close persistence as the forecasting reference; this checkpoint has not demonstrated an advantage. On 16,872 windows across 37 stocks, it improves MAE for 0 stocks. Macro price-normalized MAE is 4.29%, versus 1.26% for persistence. Those percentages measure price error relative to each stock's mean price; they are not returns or directional accuracy.

Failure example: ATO's MAE is $9.90**, versus **$1.07. Its average signed forecast error is $-9.90, and 77.0% of its target prices lie outside its training Close range. The displayed final 50 observations show forecasts remaining below actual prices. This is consistent with level bias under a shifted price range, but does not establish the cause; not every failure can be attributed to range shift.

What was verified: all 37 saved scalers match the available training-data refits. Evaluation target dates span 2024-02-13–2025-12-05. The test warm-up was excluded, and every ticker remains in the saved error table.

Next development experiment: compare a last-close-plus-predicted-change model and a simple regularized regression on a strictly chronological development split. Review the unusual encoder/pooling configuration and carry only already observed history across boundaries. Select settings using development data, then confirm on a new held-out period; the 2024–2025 audit has now been inspected. No claim about improved predictions should be made until that comparison supports it.
